BM25 and Lexical Keyword Search

BM25, short for Best Matching 25, is a ranking function that scores documents by how well their exact terms match a query. It has been the backbone of search engines since the 1990s and remains a strong baseline that neural retrieval frequently fails to beat outright.

BM25 combines three signals. Term frequency rewards documents that contain a query term more often, but with saturation: the tenth occurrence of a term adds far less than the second, preventing keyword stuffing from dominating the ranking. Inverse document frequency rewards rare terms, so matching an unusual word like "PagedAttention" counts for far more than matching a common word like "system". Length normalization prevents long documents from scoring highly merely because they contain more words overall.

Two tunable parameters control this behavior. The k1 parameter controls how quickly term frequency saturates, typically set between 1.2 and 2.0. The b parameter controls the strength of length normalization, typically 0.75, where 0 disables it entirely and 1 applies it fully.

Lexical search remains essential in a world of embeddings because it succeeds precisely where dense retrieval fails. Exact identifiers such as error codes, SKUs, version numbers, function names, and legal citations must match literally. An embedding model that never encountered the string "ORA-01555" during training places it somewhere arbitrary in vector space, and semantic similarity cannot recover it. BM25 finds it immediately because it treats the token as a token.

The weakness of BM25 is the vocabulary mismatch problem. A query asking about "car" will not match a document that only ever says "automobile", because there is no notion of meaning in the scoring function, only term overlap.

This complementary failure profile is the entire justification for hybrid search. Dense retrieval handles paraphrase and synonymy; lexical retrieval handles rare exact tokens. Systems that combine both consistently outperform either one alone.
