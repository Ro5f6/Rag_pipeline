Graph RAG and Structured Knowledge

Graph RAG replaces or supplements the flat chunk index with a knowledge graph of entities and the relationships between them, retrieving connected subgraphs rather than isolated passages.

The construction step uses a language model to extract entities and relations from each document, producing triples such as service A depends on database B. These accumulate into a graph where the same entity mentioned across many documents becomes a single node with many edges.

The retrieval advantage is on questions requiring aggregation across documents. Asking what depends on a deprecated service is nearly impossible with chunk retrieval, because the answer exists as ten separate mentions in ten separate documents and no single chunk contains it. A graph traversal answers it directly by walking edges into the node.

Community summarization extends this further. Clustering the graph and having a model write a summary of each cluster produces material that answers broad thematic questions such as what the main reliability risks in a system are. These questions have no single answering passage, so ordinary retrieval fails on them by construction.

The costs are real. Graph construction requires a model call over every document, making ingestion far more expensive than embedding. The extracted graph inherits the extraction model's errors, and a wrong edge propagates into every traversal that crosses it. Keeping the graph current as documents change is substantially harder than re-embedding a chunk.

Graph RAG and vector RAG are complementary rather than competing. Vector retrieval excels at locating specific passages answering specific questions. Graph retrieval excels at relationship and aggregation questions. Production systems frequently run both and fuse the results, which is the same reciprocal rank fusion pattern applied to a third retriever.

The decision hinges on the question distribution. If users mostly ask direct factual questions, a graph adds cost without benefit. If they ask about relationships, dependencies, or themes spanning many documents, chunk retrieval will keep failing no matter how well it is tuned.
